# AMADORA · מערכת ניהול הזמנות

מערכת אדמין לניהול הזמנות: סטטוסים, זמני אספקה (14 ימי עסקים), תשלומים וגבייה.
האתר מתארח ב-**Vercel**, הנתונים וההתחברות ב-**Supabase**, והקוד כאן ב-**GitHub**.
אין ספריות חיצוניות ואין שלב בנייה: כל שינוי שנשמר כאן עולה לאוויר תוך דקה.

---

## הפעלה ראשונה (פעם אחת, כ-15 דקות)

### שלב 1: בסיס הנתונים ב-Supabase
1. נכנסים לפרויקט ב-supabase.com.
2. בתפריט הצד: **SQL Editor** ← **New query**.
3. פותחים את הקובץ [`supabase/setup.sql`](supabase/setup.sql) כאן ב-GitHub, מעתיקים את **כל** התוכן, מדביקים ולוחצים **Run**.
   הפעולה יוצרת את הטבלאות ואת כללי העבודה, ומכניסה את החגים ואת 7 ההזמנות מהאקסל. היא בטוחה להרצה חוזרת.

### שלב 2: משתמש הכניסה
1. ב-Supabase: **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. מזינים מייל לכניסה המשותפת (למשל `office@amadora-jewelry.com`, לא חייב להיות מייל אמיתי) וסיסמה חזקה.
   מסמנים **Auto Confirm User** ויוצרים.
3. **חשוב לאבטחה:** **Authentication** ← **Sign In / Providers** (או **Providers ← Email**): מכבים את **Allow new users to sign up**.
   כך אף אחד לא יוכל לפתוח לעצמו משתמש.

### שלב 3: המפתחות
ב-Supabase: **Project Settings** ← **API** (או **API Keys**). מעתיקים:
- **Project URL**
- המפתח הציבורי: **anon / publishable**

> המפתח הסודי (**service_role / secret**) נדרש רק לחיבורים חיצוניים בעתיד. אל תשתפו אותו עם אף אחד ואל תדביקו אותו בצ'אט.

### שלב 4: העלאה ל-Vercel
1. ב-vercel.com: **Add New…** ← **Project** ← בוחרים את המאגר `amadora-orders` ← **Import**.
2. **Framework Preset:** `Other`. אין צורך לשנות שום הגדרת בנייה.
3. פותחים **Environment Variables** ומוסיפים:

| שם | ערך |
|---|---|
| `SUPABASE_URL` | ה-Project URL מהשלב הקודם |
| `SUPABASE_ANON_KEY` | המפתח הציבורי (anon / publishable) |
| `LOGIN_EMAIL` | המייל של משתמש הכניסה משלב 2 |

4. **Deploy**. אחרי כדקה מקבלים קישור (למשל `amadora-orders.vercel.app`) וזהו.

אם משנים משתני סביבה אחרי ההעלאה: **Deployments** ← שלוש נקודות ליד הגרסה האחרונה ← **Redeploy**.

**דומיין משלכם (רשות):** ב-Vercel ← **Settings** ← **Domains** ← למשל `orders.amadora-jewelry.com`, ומוסיפים את רשומת ה-DNS ש-Vercel מציג.

## איך נכנסים
קישור + השם שלך + הסיסמה המשותפת. השם נשמר בהיסטוריית כל הזמנה (מי שינה מה ומתי).
**החלפת סיסמה:** Supabase ← Authentication ← Users ← המשתמש ← Reset / Update password.
**משתמשים נפרדים:** אפשר ליצור משתמש לכל עובד באותו מקום. אם מוחקים את `LOGIN_EMAIL` מ-Vercel, מסך הכניסה יבקש גם מייל.

## כללי העבודה (נאכפים בבסיס הנתונים, גם לחיבורים חיצוניים)
- **מספור:** הזמנות חדשות מתחילות ב-2772 ועולות ב-1. הזמנה שנדחתה לא "שורפת" מספר.
- **פתיחת הזמנה:** חובה להזין כמה שולם (מותר 0). אם הסכום גדול מ-0, חובה לבחור גם איך שולם. סימון חשבונית הוא תיבת סימון.
- **מעבר ל"מוכן למסירה" או ל"אצל הלקוח":** חובה להזין את השלמת התשלום (כמה נותר לשלם, איך שולם, חשבונית). המערכת מציעה אוטומטית מחיר מכירה פחות המקדמה.
- **מחיר לפני מע"מ:** מחיר מכירה ÷ 1.18 (אחוז המע"מ ניתן לשינוי בהגדרות).
- **זמן אספקה:** 14 ימי עסקים (ראשון עד חמישי, בלי חגים), נספרים מהיום שאחרי כניסת ההזמנה. התראה כשנותרו 6 ימים, התראה דחופה כשנותרו 3. המונה נעצר כשההזמנה עוברת ל"אצל הלקוח".
- **חגים:** 2026 עד 2030 כבר בפנים (פסח, שביעי של פסח, יום העצמאות, שבועות, ראש השנה, יום כיפור, סוכות, שמיני עצרת). אפשר להוסיף או להסיר במסך ההגדרות.
- **מחיקה:** הזמנה נמחקת לסל המחזור ואפשר לשחזר אותה. מחיקה לצמיתות אפשרית רק מתוך סל המחזור.

## חיבורים חיצוניים (וואטסאפ, ManyChat, Shopify, Make)
נקודת API מוכנה: `/api/orders`. כדי להפעיל אותה מוסיפים ב-Vercel עוד שני משתנים:

| שם | ערך |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | המפתח הסודי מ-Supabase |
| `INTEGRATION_API_KEY` | סיסמה ארוכה שתמציאו (לפחות 32 תווים) ותזינו גם במערכת החיצונית |

כל קריאה שולחת את הכותרת `x-api-key: <INTEGRATION_API_KEY>`.

**בדיקת סטטוס הזמנה** (למשל בוט "איפה ההזמנה שלי?" ב-ManyChat):
```
GET /api/orders?number=2772
→ { "order_number": 2772, "customer_name": "...", "status": "factory", "status_label": "ייצור – מפעל", ... }
```

**פתיחת הזמנה מבחוץ** (למשל מ-Shopify דרך Make):
```
POST /api/orders
{ "customer_name": "...", "customer_phone": "...", "description": "...", "sale_price": 4000,
  "payment1_amount": 2000, "payment1_method": "אתר", "payment1_invoice": true, "source": "Shopify" }
```
אמצעי תשלום אפשריים: מזומן, העברה בנקאית, אשראי, שת"פ, פייבוקס, ביט, אתר.

## מבנה הקבצים
```
public/            האתר (נטען כמו שהוא, בלי בנייה)
  index.html
  app/main.js      כניסה, ניווט, פעולות משותפות
  app/views.js     כל המסכים
  app/logic.js     סטטוסים, ימי עסקים, מע"מ, גבייה, בדיקות
  app/api.js       חיבור ל-Supabase (ומצב הדגמה מקומי)
  app/ui.js        רכיבי ממשק
  app/xlsx.js      ייצוא לאקסל
  app/styles.css   עיצוב
api/               פונקציות שרת ב-Vercel
  config.js        מעביר לדפדפן את כתובת Supabase והמפתח הציבורי
  orders.js        נקודת API לחיבורים חיצוניים
supabase/
  setup.sql        הקמה מלאה (schema.sql + seed.sql)
```

**הרצה מקומית לבדיקה:** `cd public && python3 -m http.server 8000`, ואז פותחים את `http://localhost:8000`.
בלי חיבור ל-Supabase האתר נפתח ב**מצב הדגמה** (סיסמה: `demo`), עם נתוני דוגמה שלא נשמרים.
